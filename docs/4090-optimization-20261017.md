# RTX 4090 optimization: 2026-10-17

## Results

Complete house scene, 6000x4000, 64 spp (1,536,000,000 attempted paths), seed 77, native minimum aperture, dispersion enabled, prescribed native sensor plane, fused mirror reuse. NVIDIA RTX 4090, driver 610.88, Chrome 155.0.8059.82; headed 1280x720 viewport at DPR 1. No PIX injection during benchmarks.

| Lens | Baseline ms | Parallel statistics only ms | Final ms | Wall-time reduction | Throughput speedup |
|---|---:|---:|---:|---:|---:|
| canon-fl-50mm-f1-8 | 4803.4 | 4439.6 | 4159.8 | 13.4% | 1.155x |
| sony-fe-600mm-f4-gm-oss | 2555.7 | 2307.1 | 2202.6 | 13.8% | 1.160x |

Times are arithmetic means of six measured trials per lens/version across two fresh browser sessions. Each session has one excluded warmup and three measured trials. Order: baseline -> statistics -> final -> final -> statistics -> baseline. Rendering ends only after the GPU queue completes. Compilation, pupil preparation, readback and hashing are outside the render interval. Repeats within one session are correlated; this is a controlled comparison of these two lenses, not a universal speedup claim. The raw table includes medians and min/max values.

The baseline is commit dbfdffb with only the raw integrator's CRLF normalized to LF at the diagnostic server. Unmodified Windows sources have invalid bind groups and zero real samples, so their apparent completion time is not a valid performance baseline. Source snapshots for baseline, statistics-only and final are stored separately.

## Implemented changes

- Shared WORK-COUNTING stripping handles LF, CRLF and an EOF marker. The split mirror coordinate transformation also accepts CRLF. This removes the accidental diagnostic storage binding from normal pipelines.
- Statistics use parallel 4096-pixel blocks (5860 workgroups for the 24MP single-tile case), followed by a small GPU reduction of their partial results. Small tiles need only the first pass. Readback remains one aligned result slot per tile; temporary partials are released, and stale snapshots are discarded after a reset/revision change. The temporary partial buffer is about 275 KiB for 24MP.
- Optical tracing computes the wavelength's LUT coordinate once per ray, caches the previous transmitted medium's index when the next interface refers to the same record, and reads post-intersection surface fields after the root solver instead of retaining the full surface across it. Non-contiguous medium records fall back to a fresh lookup. The arithmetic of refraction, intersection, wavelength sampling and accumulation is unchanged.

## Statistics query timing

Each lens/version has ten isolated queries across two browser sessions, outside timed rendering. Median:

- canon-fl-50mm-f1-8: 66.10 -> 3.55 ms, 18.6x. These are isolated queue-complete query wall times, including temporary buffers and readback.
- sony-fe-600mm-f4-gm-oss: 66.50 -> 3.10 ms, 21.5x. These are isolated queue-complete query wall times, including temporary buffers and readback.

This query speedup is not the end-to-end application speedup. Queries run approximately once per second and at completion; the table above measures their actual application impact.

Every byte of the 24MP accumulation image was read after timing and SHA-256 hashed: all three versions and both sessions match for each lens, including XYZ and all counters. Each full readback is 1,536,000,000 bytes.

- 199 Node tests passed; final production build passed (existing chunk-size advisory remains).
- GPU statistics tests passed at 1, 4095, 4096, 4097, 100003 and 24000000 pixels, with independent CPU expected counters.
- Mirror/retraced-reference, odd sizes, forced multi-buffer storage, Sony lens, work-counting and true split-mode GPU tests passed.
- Repeated engine statistics calls release temporary partials; a reset while statistics is pending returns no stale snapshot.
- Native-gap GPU checks passed after fixing the fixture to use the same independent per-pixel sampling sequence as its CPU reference. The old fixture compared a finite independent sequence to default shared-mirror samples and failed identically on baseline and candidate; no tolerance was loosened.
- Existing runtime-gpu.html still has an obsolete assertion requiring GPU AF beam-budget fields although focus now uses a CPU worker. Baseline and candidate fail at that assertion. It is not counted as passed, and this work does not change autofocus behavior. Dedicated statistics lifecycle checks above cover the changed resource/revision behavior.

Hierarchical floating-point statistics can change the last rounding bits of aggregate rates. Integer partial accumulation and the existing nonnegative counter semantics are retained; the underlying per-pixel accumulation is byte-identical. No claim is made that register count dropped to a specific number: only the measured application/kernel effects are reported.

## Rejected experiments

Shortening the lifetime of the entire previous pixel record via a zeroed delta record regressed full-scene performance. Restricting quadrant-loop unrolling and reusing wavelength-only spectral exponentials did not produce a stable gain. Those changes are not in the final source. Their raw tests are under reports/triage*.json; the interrupted first campaign is exploratory and excluded from the final table. The optical-core-only triage on the same full house at 2400x1600 reduced queue-complete computation time by about 6% Canon and 4.5% Sony, with complete accumulation hashes matching, before the final 24MP application comparison.
